1. VISÃO GERAL
================================================================================

O Muhsic é uma aplicação web estática (sem servidor, sem build, sem framework)
composta por duas páginas:

  index.html   →  Página inicial. Apresenta o projeto e abre o modal de
                  login / cadastro. Ao entrar, salva a sessão e redireciona.

  muhsic.html  →  O player. Só abre com uma sessão válida. Contém a barra
                  lateral, as telas (Início, Buscar, Biblioteca, Detalhe),
                  a vitrola, o painel maximizado e o modal de configurações.

Mídias (músicas, capas, logos, sons) ficam hospedadas no Cloudinary. Os
"bancos de dados" são arquivos .js com arrays. Preferências do usuário ficam
no localStorage do navegador.

    ┌────────────────────┐      login ok       ┌────────────────────────┐
    │     index.html     │ ──────────────────▶ │      muhsic.html       │
    │  landing + modal   │   (salva sessão)    │   player / biblioteca  │
    └────────────────────┘ ◀────────────────── └────────────────────────┘
                                 logout / sem sessão

2. PRINCÍPIOS DA ARQUITETURA
================================================================================

  • SEPARAÇÃO EM CAMADAS
      config → data → core → app/pages → main
      Cada camada só usa as camadas anteriores.

  • UMA RESPONSABILIDADE POR ARQUIVO
      Ex.: queue.js só cuida da fila; themes.js só cuida dos temas.

  • FONTE ÚNICA DA VERDADE
      Planos só em plans.js; URLs e números "mágicos" só em app.config.js;
      leitura do catálogo só em core/library.js; localStorage só via Store.

  • SEM ETAPA DE BUILD
      Scripts clássicos (<script src>) compartilham o escopo global. Isso
      permite abrir o index.html direto do disco (file://), algo que
      módulos ES (import/export) não permitem sem um servidor.

  • TROCA FÁCIL DO "BACKEND"
      Para usar uma API real no futuro, basta substituir js/data/ e
      js/core/storage.js; a interface não precisa mudar.

5. ORDEM DE CARREGAMENTO DOS SCRIPTS
================================================================================

Como os scripts compartilham o escopo global, a ORDEM IMPORTA: um arquivo
pode usar, no momento em que é lido, apenas o que veio antes. Funções só são
CHAMADAS depois que todos carregam (no evento DOMContentLoaded), então
módulos do mesmo nível podem se chamar entre si.

  index.html                         muhsic.html
  ─────────────────────────          ─────────────────────────────────
  1  config/app.config.js            1  config/app.config.js
  2  config/plans.js                 2  config/plans.js
  3  data/users.js                   3  data/songs.js
  4  core/storage.js                 4  core/storage.js
  5  core/utils.js                   5  core/utils.js
  6  core/session.js                 6  core/session.js
  7  core/auth.js                    7  core/library.js
  8  pages/landing.js                8  app/state.js
                                     9  app/colors.js
                                    10  app/vinyl.js
                                    11  app/player.js
                                    12  app/queue.js
                                    13  app/likes.js
                                    14  app/player-events.js
                                    15  app/max-panel.js
                                    16  app/views/cards.js
                                    17  app/views/home.js
                                    18  app/views/sidebar.js
                                    19  app/views/detail.js
                                    20  app/views/shelf.js
                                    21  app/navigation.js
                                    22  app/themes.js
                                    23  app/user-ui.js
                                    24  app/main.js   ← sempre por último

Além disso, muhsic.html tem um pequeno <script> inline no <head> que
redireciona para o login ANTES de desenhar a página, caso não exista sessão.

7. ORGANIZAÇÃO DO CSS
================================================================================

  index.html  carrega  css/site.css   → variables, reset, effects, keycaps,
                                        pages/landing
  muhsic.html carrega  css/app.css    → todo o resto, na ordem abaixo

  Ordem da cascata em css/app.css:

    1. base/variables, reset, effects, components/keycaps
    2. layout/app, sidebar, header
    3. components/ad-banner, folder-cards, vinyl-shelf
       pages/detail
       components/search, login-animation
    4. player/deck, turntable, queue, overlays
    5. components/settings-modal, player/max-panel
    6. base/responsive     ← @media sempre depois dos componentes
    7. themes/themes       ← acabamentos sobrescrevem as variáveis

  Identidade visual (tokens em base/variables.css):
    Superfícies ..... --bg-screen, --bg-panel, --bg-inset, --wood-grain
    Texto ........... --text-primary, --text-secondary, --text-muted
    Acento .......... --accent (trocado pelo tema) e derivados calculados
                      com color-mix(): --accent-soft, --accent-glow,
                      --accent-dark, --stripes-v, --stripes-h
    Cores fixas 80s . --mustard, --brick, --teal, --cobalt, --plum, --cream
    Teclas .......... --key-top, --key-side, --key-edge, --key-text
    LCD ............. --lcd-bg, --lcd-text, --lcd-glow
    Fontes .......... --font (Rubik), --font-display (Bungee),
                      --font-lcd (VT323)

  Componentes reutilizáveis:
    .key ............ tecla bege. Variações: --accent, --mod, --sm, --lg,
                      --icon, --block. data-legend="F1" mostra legenda;
                      .active acende o LED.
    .kbd ............ tecla desenhada (tabelas de controles)
    .panel .......... painel com parafusos nos cantos
    .lcd-text ....... texto de visor âmbar
    .stripes ........ faixa de 4 cores
    .crt (no body) .. scanlines + vinheta sobre a tela inteira

  Estados controlados pelo JavaScript (classes no <body>):
    is-playing ........ disco tocando: LED aceso, VU animado, botão vira pausa,
                        logo do rack gira
    is-dragging-disc .. um disco está sendo arrastado: o prato pulsa e
                        aparece "SOLTE O DISCO AQUI"

  Vitrola escalável:
    O toca-discos é desenhado numa "stage" fixa de 300×300 px e reduzido
    com transform: scale(var(--tt-scale)). Assim a geometria do braço
    (pivô, comprimento e ângulos 6°/24°) nunca quebra em telas menores.
    O modo vitrine usa o mesmo princípio com --max-scale.

  Como funcionam os temas:
    Todo o visual usa variáveis (ex.: var(--accent)). O JavaScript define
    <body data-theme="red"> e o bloco body[data-theme="red"] em themes.css
    troca o --accent; os tons derivados são recalculados no <body>.
    O tema "light" (Papel) também troca as superfícies e o texto.

8. MODELOS DE DADOS
================================================================================

  USUÁRIO (data/users.js e contas criadas)
  ┌───────────┬──────────────────────────────────────────────────────────┐
  │ id        │ número único (0 é reservado para "global")               │
  │ login     │ nome usado para entrar                                   │
  │ pass      │ senha (texto puro — simulação)                           │
  │ name      │ nome exibido                                             │
  │ plan      │ 'free' | 'plus' | 'premium'                              │
  │ avatar    │ URL (opcional)                                           │
  │ email     │ apenas contas criadas pelo formulário                    │
  └───────────┴──────────────────────────────────────────────────────────┘

  MÚSICA (data/songs.js)
  ┌────────────┬─────────────────────────────────────────────────────────┐
  │ id         │ número único                                            │
  │ title      │ nome da música                                          │
  │ artist     │ artista                                                 │
  │ category   │ 'playlist' | 'album' | 'genre'                          │
  │ playlist   │ nome da playlist  (se category = 'playlist')            │
  │ album      │ nome do álbum     (se category = 'album')               │
  │ genre      │ nome do gênero    (se category = 'genre')               │
  │ coverImage │ URL da capa                                             │
  │ url        │ URL do áudio (.mp3)                                     │
  │ duration   │ segundos (aproximado; corrigido em segundo plano)       │
  │ userIds    │ [0] todos · [1] só o usuário 1 · [1,2] usuários 1 e 2   │
  └────────────┴─────────────────────────────────────────────────────────┘

  As coleções (álbuns, playlists, gêneros) NÃO são cadastradas à parte:
  elas surgem automaticamente agrupando as músicas pelo campo da categoria.

  SESSÃO (localStorage)
    { id, name, plan, avatar }

9. PERSISTÊNCIA (localStorage)
================================================================================

  ┌───────────────────────┬────────────────────────────────────────────────┐
  │ Chave                 │ Conteúdo                                       │
  ├───────────────────────┼────────────────────────────────────────────────┤
  │ muhsic_session        │ usuário logado { id, name, plan, avatar }      │
  │ muhsic_users          │ contas criadas pelo formulário [ ... ]         │
  │ muhsic_theme_<id>     │ tema escolhido por cada usuário ("blue")       │
  │ muhsic_likes_<id>     │ { songs:[ids], albums:[nomes], genres:[nomes] }│
  │ muhsic_lastSongId     │ última música tocada                           │
  └───────────────────────┴────────────────────────────────────────────────┘

  Curtidas guardam só IDs/nomes; ao abrir o app elas são reconstruídas com
  os dados atuais do catálogo. Se uma música sair do catálogo (ou deixar de
  ser visível para o usuário), ela some das curtidas sem quebrar nada.

  Para limpar tudo durante uma apresentação: DevTools (F12) → Application →
  Local Storage → botão "Clear".

10. FLUXOS PRINCIPAIS
================================================================================

  ── LOGIN ────────────────────────────────────────────────────────────────
   Usuário envia o formulário (index.html)
     └▶ landing.js → validarCredenciais()          [core/auth]
          ├ falhou  → mensagem "Usuário ou senha inválidos."
          └ ok      → salvarSessao()               [core/session]
                       └▶ redireciona para muhsic.html

  ── ABERTURA DO PLAYER ───────────────────────────────────────────────────
   <head> inline: sem sessão? → volta para index.html
   state.js:      lê a sessão e o plano
   main.js → initMuhsic()
     1. loadTheme()               aplica data-theme no <body>
     2. cacheDomRefs()            guarda os elementos da tela
     3. applyUserToUI()           nome, plano, anúncio, bloqueio de temas
     4. carregarCurtidas()        curtidas salvas do usuário
     5. bind*()                   todos os eventos
     6. initApp()
          renderHome → renderSidebar → renderLibrary → renderSearchResults
          prepararPrimeiraFaixa (engatilha sem tocar) → buildQueue
          sincronizarDuracoesBiblioteca (em segundo plano)
     7. showLoginAnimation()

  ── TOCAR UMA MÚSICA ─────────────────────────────────────────────────────
   clique no vinil → togglePlay()
     └▶ pendingPlay = true; braço desce (classe .active)
          └▶ "transitionend" do braço → audio.play()
               └▶ evento "play" → startSpin(), destaque na lista,
                                  salva muhsic_lastSongId

  ── PRÓXIMA FAIXA ────────────────────────────────────────────────────────
   girar o vinil ≥ 60° / tecla → / fim da música
     └▶ nextTrack()
          ├ fila tem itens → toca autoQueue[0], shiftQueue() completa a fila
          └ fila vazia     → aleatório (biblioteca) ou próxima da lista

  ── FAIXA ANTERIOR ───────────────────────────────────────────────────────
   prevTrack()
     ├ tocou > 3s → volta ao início da mesma faixa
     ├ há histórico → toca a última de playHistory
     └ senão → faixa anterior da lista ativa

  ── CURTIR ───────────────────────────────────────────────────────────────
   duplo clique no vinil → toggleLikeCurrent()
     └▶ altera likedSongs → salvarCurtidas() → renderSidebar + renderHome

  ── TROCAR TEMA ──────────────────────────────────────────────────────────
   Menu do perfil → Acabamento do aparelho → clique na cor → applyTheme()
     ├ plano sem temas → ignora (grade aparece bloqueada)
     └ ok → <body data-theme> + salva muhsic_theme_<id>

11. GUIA: COMO ADICIONAR NOVAS FUNCIONALIDADES
================================================================================

  ── Nova música ──────────────────────────────────────────────────────────
   1. Suba o .mp3 e a capa no Cloudinary.
   2. Adicione um objeto em js/data/songs.js com um id ainda não usado.
   3. Defina userIds ([0] para todos).
   Se o nome de álbum/playlist/gênero for novo, a pasta é criada sozinha.

  ── Novo usuário de teste ────────────────────────────────────────────────
   Adicione em js/data/users.js. Use um id novo e um plano de plans.js.

  ── Novo plano ───────────────────────────────────────────────────────────
   1. Adicione a entrada em js/config/plans.js.
   2. Inclua a <option> no <select id="regPlan"> do index.html.

  ── Novo tema ────────────────────────────────────────────────────────────
   1. Adicione o nome em THEMES (js/config/app.config.js).
   2. Crie body[data-theme="nome"] { ... } em css/themes/themes.css.
   3. Adicione o botão .theme-swatch no modal em muhsic.html.

  ── Novo componente visual (CSS) ─────────────────────────────────────────
   1. Crie o arquivo em css/components/ (ou player/, layout/).
   2. Importe-o em css/app.css ANTES de base/responsive.css.
   3. Regras responsivas do componente vão em base/responsive.css.

  ── Nova tela / funcionalidade em JS ─────────────────────────────────────
   1. Regra sem interface?  → crie/edite um arquivo em js/core/.
      Interface?            → crie em js/app/ (ou js/app/views/).
   2. Adicione o <script> em muhsic.html na camada certa,
      sempre ANTES de js/app/main.js.
   3. Se precisa de eventos, crie uma função bindAlgo() e chame-a em
      initMuhsic() usando etapa('nome', bindAlgo).
   4. Valores configuráveis → PLAYER ou ASSETS em app.config.js.
   5. Dados salvos → nova chave em STORAGE_KEYS + uso via Store.

  ── Trocar por um backend real ───────────────────────────────────────────
   • js/data/*.js       → chamadas fetch() para a API
   • core/auth.js       → POST /login e POST /register
   • core/storage.js    → manter só para preferências locais
   O restante do app não precisa mudar.

12. CONVENÇÕES DE CÓDIGO
================================================================================

  • Indentação de 4 espaços, UTF-8, ponto e vírgula no fim das instruções.
  • Cada arquivo começa com um cabeçalho:
        /* ===== MUHSIC — PASTA / ARQUIVO =====  descrição  ===== */
  • Constantes globais em MAIÚSCULAS (PLAYER, ASSETS, QUEUE_SIZE).
  • Funções de interface: render*() desenham, bind*() ligam eventos.
  • Nomes em português ou inglês são mantidos como no código original para
    preservar o histórico; novos nomes seguem o idioma do arquivo.
  • Texto vindo de usuário ou do catálogo entra no HTML via escapeHTML().
  • localStorage é acessado SOMENTE pelo objeto Store.
  • Nenhuma lógica no HTML além do guarda de sessão do <head>.

13. LIMITAÇÕES CONHECIDAS
================================================================================

  • Senhas em texto puro e autenticação no navegador: aceitável apenas por
    ser uma simulação acadêmica. Não usar com dados reais.
  • Dados salvos ficam apenas no navegador atual (não sincroniza).
  • Gestos do vinil usam mouse; em telas de toque use o teclado da vitrola
    (play, próxima, anterior, volume...). Arrastar discos também depende
    de mouse (drag & drop nativo do HTML).
  • O visual usa color-mix() do CSS: navegadores de 2023 em diante
    (Chrome 111+, Firefox 113+, Safari 16.2+).
  • Os botões ♥/+ salvam apenas álbuns; em playlists ainda não fazem nada.
  • Depende de internet para Cloudinary, Font Awesome e Google Fonts.
